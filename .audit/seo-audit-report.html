Critical · read this first

The site is telling Google it isn't the real thing

Four independent audits (technical, sitemap, schema, GEO) each surfaced the same defect from different angles: every canonical tag, the sitemap, and every JSON-LD block on new.mindlind.de declares mindlind.de as the authoritative URL. But mindlind.de is a separate, live WordPress site — different business name, different registered address (Düsseldorf vs. this site's Vilnius), different logo, different portfolio. Two of the declared canonical targets (/agency, /projects) 404 on that domain; two more resolve only through a redirect to different slugs.

Meanwhile new.mindlind.de itself is fully public and indexable (Allow: /, index, follow, no auth wall). Google will either index the staging build directly as an orphan (its own sitemap and llms.txt route crawlers back to the wrong domain), or fold it into a canonical target that doesn't exist — and in the meantime two real business identities are colliding under one schema @id. This is the first thing to resolve; most High-severity findings below are downstream of it.

02Critical Findings

Critical

Canonical / schema / sitemap all point off-domain to a conflicting live business

technical · sitemap · schema · geo
Observation
Every tested page's <link rel="canonical">, JSON-LD @id/url, OG tags, and the 15-URL sitemap.xml reference mindlind.de. robots.txt also declares Sitemap: https://mindlind.de/sitemap.xml — a cross-domain pointer to a different, WordPress-generated sitemap entirely.
Why it matters
This blocks correct indexing regardless of any other fix — schema enrichment, content rewrites, and GEO citability all inherit whichever domain ends up "real" to Google. It's the dependency root for roughly a third of the findings in this report.
Falsifiability
curl -I https://mindlind.de/agency → 404 (reproduced). curl -I https://mindlind.de/projects → 404 (reproduced). GSC URL Inspection on new.mindlind.de/agency would show "Google-selected canonical" pointing at a 404 if this is live in Search Console.
Watch
GSC "Duplicate, Google chose different canonical" and "Crawled — currently not indexed" counts for the new.mindlind.de property.
Critical

Impressum & Datenschutz return 200 but contain no legal content, and aren't linked anywhere

content
Observation
/impressum and /datenschutz resolve successfully but render only header/footer chrome — no Handelsregister/USt-ID, no named data controller, no GDPR disclosures. Neither is linked from any page's navigation or footer that was crawled.
Why it matters
For a German-language commercial site this is a Telemediengesetz/DDG §5 Impressumspflicht compliance risk independent of the domain issue above — it needs fixing regardless of which host goes to production.
Falsifiability
Load /impressum in a browser: fewer than ~150 words of substantive legal content (company/register data, USt-ID, responsible person) confirms the gap.
Watch
Word count on both pages, and presence of a footer link to each from every template.
Critical

Homepage 3D scene blocks the main thread for 5.5 seconds — severe INP risk

performance
Observation
A single JS chunk running an embedded Spline 3D scene consumes 7.9s of scripting time from two .splinecode payloads totaling ~11.1MB — ~95% of the homepage's 13.3MB total weight. Lab Total Blocking Time (the standard proxy for INP): 5,510ms on the homepage vs. 130ms and 80ms on Services/Projects.
Why it matters
Any tap or click during/after load queues behind this — real-world INP will land far past "poor" for a meaningful share of visits, on the one page every prospective client lands on first. Notable given the agency's own pitch is performance marketing.
Falsifiability
Re-run Lighthouse with --blocked-url-patterns="*spline.design*"; TBT should drop by several seconds if this attribution holds.
Watch
bootup-time for the Spline chunk specifically, and homepage TBT on every deploy — set a CI budget (fail >1,000ms).
Critical

Web Design and Branding — the agency's two flagship services — have zero visible copy on /services

sxo · schema
Observation
The Service schema on /services lists 5 offerings, but only Instagram Ads, SEO, and Google Ads have a visible price card and body text. "Webdesign"/"Web-Design" and "Branding" appear only inside <meta> and JSON-LD — never once in rendered <body> text.
Why it matters
Someone searching "Webdesign Agentur" or "Branding Agentur" — almost certainly this agency's highest-value queries — lands on a page that reads to Google, and to the visitor, as a paid-ads retainer page. Persona scoring below quantifies the impact: 18–32/100 for exactly these two buyer types.
Falsifiability
Raw HTML search on /services body for "Branding"/"Webdesign" outside <head>/<script>: zero matches as of 2026-08-17.
Watch
/services word count (currently 324 total, ~70–90 unique) — target real growth once Web Design/Branding sections ship.

performance
Observation
TTFB and resource-load are fast everywhere (~300ms), but "element render delay" — the gap between resource-ready and actual paint — is 47–68% of total LCP time on Home, Services, and Projects alike. 06Prioritized Action Plan

Phase 0

Decide the domain strategy — this gates everything else

now
  1. Choose: is new.mindlind.de becoming production, or is it pre-launch staging for a future cutover to mindlind.de?
    • Going live as-is: repoint every canonical, JSON-LD @id/url, sitemap <loc>, OG tag, and llms.txt link to new.mindlind.de (or the intended final host) using resolved, non-redirecting paths.
    • Still staging: add X-Robots-Tag: noindex and block via robots.txt or Vercel deployment protection until cutover, then flip canonicals and set up 301s from the old WordPress slugs at launch.
Phase 1

Critical — fix regardless of the domain decision

this week
  1. Write real legal content for Impressum and Datenschutz; link both from the sitewide footer.
  2. Defer/lazy-load the Spline 3D scene behind an intersection observer; compress the .splinecode assets; stop gating the homepage LCP element behind it.
  3. Write real body copy and pricing for Web Design and Branding on /services — they already have schema stubs with no matching visible content.
Phase 2

High — most depend on the Phase 0 decision

within 1 week
  1. Regenerate sitemap.xml and JSON-LD @id/url for the correct final host. depends on Phase 0
  2. Regenerate llms.txt against the same host. depends on Phase 0
  3. Add Content-Security-Policy and X-Frame-Options on both domains; add includeSubDomains; preload to HSTS.
  4. Consolidate the duplicated FAQ to one canonical page; link to it from the others instead of repeating it.
  5. Attribute the homepage's headline stats to specific named case studies; add at least one quotable metric per case study.
  6. Add one real third-party trust signal: LinkedIn company page in sameAs, a named client testimonial, or a directory listing.
  7. Add descriptive alt text to project/portfolio images.
Phase 3

Medium — optimization

within 1 month
  1. Add logo (square, ≥112px), priceRange, and geo to the Organization schema; add image/description to each CreativeWork case study.
  2. Inline critical CSS, consolidate the render-blocking chunks, and confirm the Spline runtime stays scoped to the homepage only (already true today — don't regress it).
  3. Increase mobile tap targets to ≥44px; fix the mobile menu close-icon transform.
  4. Add an above-the-fold CTA and supporting copy to /services and /projects.
  5. Expand the /projects index with a one-line summary per project, pulled out of alt text into visible body copy.
  6. Add an IndexNow key and wire submission into the deploy pipeline ahead of the eventual domain cutover.
